- `git for-each-ref --sort=-creatordate refs/tags` で v0.22.1 (2026-09-08) の直前タグは v0.22.0 (2026-08-19)。メンテナンスブランチは無く、両タグとも `main` 上にある
- `git merge-base --is-ancestor v0.22.0 v0.22.1` が真。`v0.22.0..v0.22.1` は 111 コミットで、リリースノートの各項目（What's Changed 65 件 + Documentation & Other Changes 26 件）はすべてこの範囲のコミットに対応する
- `pyproject.toml` の `version` は `0.22.0` → `0.22.1`

以上より比較元は v0.22.0 で一意に決まる。

## 調査上の注意

- 差分は 343 ファイル、+30,573 / -12,664 行。うち `src/` は 66 ファイル、+3,392 / -1,226 行。残りはテスト、ドキュメント（`docs/ja|ko|zh` の翻訳再生成を含む）、`.agents/skills` 配下のリポジトリ運用スキル、`tests/fixtures/released_api_contract.json`（公開 API 契約のスナップショット）など
- パッチリリース（`0.Y.Z` の Z）であり、[docs/release.md](https://github.com/openai/openai-agents-python/blob/v0.22.1/docs/release.md) の "Breaking change changelog" に 0.22.1 の項は追加されていない。ただし「誤った入力を黙って受理していた箇所を明示的にエラーにする」変更が複数あり、該当する使い方をしていた場合は挙動が変わる（後述の表を参照）
- 項目数が多いため、各 PR は PR 本文と `src/` 差分（変更ファイル）を確認した。以下 `[差分]` はソース差分から確認した事実、`[PR]` は PR 本文の記述、`[推測]` はそれらから読み取れる範囲での推測
- 本リリースで追加された公開 API のドキュメント（`docs/`）は、この SDK の方針（未リリース機能の docs は別 PR）により v0.22.1 時点では未整備のものがある（例: `WebSearchTool` の画像設定 [PR #4898 本文]）

## 全体の要点

新機能 6 件・修正 59 件からなる大型パッチリリース。破壊的変更は宣言されていないが、**フェイルクローズ方向の挙動変更**がいくつかある。

1. **新機能**
   - `WebSearchTool(search_content_types=["text", "image"], image_settings=...)` で Web 検索の画像結果を取得可能（#4898）
   - `RunConfig.output_guardrail_blocked_message` で、出力ガードレールに拒否されたツール出力の代替メッセージをカスタマイズ可能（#4594）
   - `MCPServerStdio` 等のローカル MCP サーバーに `tool_input_guardrails` / `tool_output_guardrails` を指定し、サーバー配下の全ツールに一括適用（#4632）
   - `UnixLocalSandboxClient(inherit_host_environment=False, host_environment_allowlist=...)` でサンドボックスへ渡すホスト環境変数を制限（#4640）
   - `DockerSandboxClientOptions(labels=...)` で Docker コンテナにラベル付与（#4564）
   - `STTModelSettings.languages` / `keywords` でストリーミング音声認識のオプション指定（#4645）、`TTSModelSettings.voice` にカスタム音声 `{"id": ...}` と新規組み込み音声を追加（#4541, #4535）、`SingleAgentVoiceWorkflow(agent, context=...)`（#4636）
2. **挙動が変わる修正（要確認）**
   - `*args: tuple[int, str]` のような固定長タプル注釈の可変長引数を持つ関数ツールは構築時に `UserError`（#4735）
   - `**kwargs` に名前付きパラメータと衝突するキーが来たら `ModelBehaviorError`（#4674）
   - `**kwargs: dict[str, int]` のスキーマが `dict[str, dict[str, int]]` に修正（#4714）、`*args: tuple[T, ...]` が `list[tuple[T, ...]]` に修正（#4655）。以前の誤ったスキーマで動いていたモデル出力は拒否される
   - `needs_approval` が callable のツールに空/欠落の引数文字列が来たら、承認判定を呼ばず中断（#4545）
   - Chat Completions で `finish_reason="length"` かつ出力が空なら `ModelBehaviorError`（#4513）、`call_id` 無しの `function_call_output` は `UserError`（#4699）
   - `OpenAIVoiceModelProvider(openai_client=..., organization=...)` は `UserError`（#4527）
   - `Runner` が暗黙に生成したモデルプロバイダは実行終了時にクローズされる（#4785）
   - `RunState` のスキーマが 1.16 → 1.17（#4564, #4613, #4630, #4698）。1.17 の JSON を旧バージョンで読むことはできない
3. **セッション（Session）の回復性強化**: 承認後の再開時に Session への書き込みが失敗しても、完了済みのツール実行・ガードレール・ハンドオフを再実行せず整合させる一連の修正（#4630, #4650, #4654, #4725, #4698）。`EncryptedSession` + 圧縮セッションの平文保存リグレッション修正（#4917、#4736 起因で v0.22.1 内で完結）
4. **トレースの機微情報**: `trace_include_sensitive_data=False` でも漏れていた STT prompt / TTS instructions / 承認拒否メッセージ・Agent repr を遮断（#4663, #4676, #4866）。逆に redacted モードでも `response_id` は残す（#4641）、ストリーミングで `response`/`input` が欠落するバグ修正（#4692）
5. **内部変更**: `RunState` のエージェント識別ロジックを `_run_state_agent_identity.py` へ抽出（#4876）、生成スパン処理の共通化（#4877）。CI・リリース手順・リポジトリスキル整備（利用者への影響なし）

変更の分類:

| 分類 | 項目 |
|---|---|
| 新機能 | #4898, #4594, #4632, #4640, #4564, #4645, #4541, #4535, #4636 |
| 挙動変更を伴う修正（誤りをエラーに） | #4735, #4674, #4714, #4655, #4545, #4513, #4699, #4527, #4785 |

| 破壊的変更・非推奨化 | 宣言されたものは無し |

## 新機能

### feat(core): Web 検索ツールで画像結果をサポート (#4898)

- PR: https://github.com/openai/openai-agents-python/pull/4898
- 変更ファイル: `src/agents/tool.py`, `src/agents/models/openai_responses.py`, `src/agents/__init__.py`

**何が変わったか** `[差分]` `WebSearchTool` に `search_content_types: list[Literal["text", "image"]] | None` と `image_settings: WebSearchToolImageSettings | None` が末尾に追加された。`WebSearchToolImageSettings` は `max_results: int`, `caption: bool` を持つ `TypedDict`（`total=False`）で、`agents` からエクスポートされる。

**変更前/後** 変更前は Responses API の web search ツールにテキスト結果しか要求できなかった。変更後は `search_content_types=["image"]`（画像のみ）や `["text", "image"]`（混在）を指定でき、`[PR]` 生の結果を得るため `web_search_call.results` の include が自動付与される。

```python
from agents import Agent, WebSearchTool

agent = Agent(
    name="搜索",
    tools=[
        WebSearchTool(
            search_content_types=["text", "image"],
            image_settings={"max_results": 3, "caption": True},
        )
    ],
)
```

**利用者への影響** 既存の位置引数とデフォルトのリクエストペイロードは不変 `[PR]`。ドキュメントは別 PR で後追い `[PR]`。

### feat(core): 出力ガードレールのブロックメッセージをカスタマイズ (#4594)

- PR: https://github.com/openai/openai-agents-python/pull/4594
- 変更ファイル: `src/agents/run_config.py`, `src/agents/run.py`, `src/agents/run_internal/blocked_output.py`, `src/agents/run_internal/run_loop.py`, `src/agents/__init__.py`

**何が変わったか** `[差分]` `RunConfig.output_guardrail_blocked_message: str | OutputGuardrailBlockedMessageFormatter | None = None` を追加。フォーマッタは `OutputGuardrailBlockedMessageArgs(default_message, guardrail_name, agent, run_context)` を受け取り `str | None` を返す**同期**関数。`__post_init__` で検証され、空文字は `ValueError`、`str` サブクラス・非 callable・コルーチン関数は `TypeError`。

**変更前/後** v0.22.0 で導入された「終端ツール出力が出力ガードレールに拒否されたら固定文 `"Output withheld by an output guardrail."` に置換する」挙動（[docs/release.md の 0.22.0](https://github.com/openai/openai-agents-python/blob/v0.22.1/docs/release.md)）が、文字列またはフォーマッタで差し替え可能になった。置換文は tripwire 例外、Session 履歴、`RunState`、ストリーミング結果、以降のモデルへのリプレイに一貫して適用される `[PR]`。フォーマッタが例外を投げたり不正値を返したりした場合は SDK デフォルトにフォールバック（フェイルクローズ）。拒否された出力本体やガードレールの `output_info` はフォーマッタに渡されない。

```python
from agents import RunConfig, OutputGuardrailBlockedMessageArgs

def jp_message(args: OutputGuardrailBlockedMessageArgs) -> str:
    return f"出力はガードレール {args.guardrail_name} により差し止められました"

run_config = RunConfig(output_guardrail_blocked_message=jp_message)
```

**利用者への影響** 追加のみ。`async def` のフォーマッタは意図的に拒否される（拒否済み出力が cancellation の traceback 等から到達可能になる余地をなくすため `[PR]`/`[差分]` コード内コメント）。

## 挙動変更を伴う修正（誤った入力をエラーにするもの）

### fix(core): 可変長引数の固定長タプル注釈を拒否 (#4735)

- PR: https://github.com/openai/openai-agents-python/pull/4735 (#4696 の議論を受けたもの)
- 変更ファイル: `src/agents/function_schema.py`

`[差分]` `def f(*args: tuple[int, str])` のような注釈は、変更前は `list[Any]` に潰れて要素制約を全て失っていた。変更後はツール構築時に `UserError("Variadic parameter `*args` ... is annotated with the fixed-length tuple ... use tuple[T, ...] or list[T] instead.")` を送出。`tuple[()]` も拒否対象、パラメータ無しの `tuple` / `typing.Tuple` は従来通り。

**移行** 該当する関数ツールがあれば、`*args: tuple[int, ...]` か `*args: list[int]` に書き換える。

### fix(core): 名前付きパラメータと衝突する `**kwargs` キーを拒否 (#4674)

- PR: https://github.com/openai/openai-agents-python/pull/4674
- 変更ファイル: `src/agents/function_schema.py`

`[PR]` `def g(*, opt: int = 1, **kw)` に `{"opt": 5, "kw": {"opt": 9}}` が来ると、変更前は検証済みの `opt=5` が黙って `opt=9` に上書きされる、または `TypeError: got multiple values` で実行が内部エラーになっていた。変更後は `FuncSchema.to_call_args()` が衝突キーを列挙した `ModelBehaviorError` を送出し、モデルにフィードバックが返る。位置専用引数（`def f(a, /, **kw)`）と `*args` の名前は予約対象外。

### fix(core): `**kwargs` の値注釈を各キーワード値に適用 (#4714) / `*args: tuple[T, ...]` の注釈を保持 (#4655)

- PR: https://github.com/openai/openai-agents-python/pull/4714, https://github.com/openai/openai-agents-python/pull/4655
- 変更ファイル: `src/agents/function_schema.py`

`[PR]` PEP 484 では `**kwargs: X` は各値の型が `X`（全体は `dict[str, X]`）。変更前は `X` が `dict[...]` の場合に一段浅く潰れていた（`**kwargs: dict[str, int]` → `dict[str, int]`）。同様に `*args: tuple[int, ...]` は `list[int]` に潰れていた。変更後は正しくネストされる（`dict[str, dict[str, int]]`、`list[tuple[int, ...]]`）。

**利用者への影響** 生成される JSON Schema が変わるため、モデルに提示される引数形が変わる。以前の（誤った）フラットな形でモデルが返していた引数は `ValidationError` → `ModelBehaviorError` になる。スカラーの `**kwargs: int`、素の `**kwargs`、通常の `*args: int` は不変。

### fix(core): 可変長ツールパラメータの `Field` 制約を保持 (#4739)

- PR: https://github.com/openai/openai-agents-python/pull/4739
- 変更ファイル: `src/agents/function_schema.py`

`[PR]` `*scores: Annotated[int, Field(ge=0)]` の制約が変更前は捨てられ、負の値がツールに到達していた。変更後は各要素/各値に制約が保持され、スキーマと実行時検証の両方で強制される。`Annotated[T, Field(...)]` 形式のみ対象。

### fix(core): 空のツール引数でフェイルクローズ (#4545)

- PR: https://github.com/openai/openai-agents-python/pull/4545
- 変更ファイル: `src/agents/util/_approvals.py`

`[PR]` `parse_function_tool_arguments` が `arguments or "{}"` としていたため、`""` や `None` が空オブジェクトになり、`needs_approval` の callable 判定（例 `"refund" in params.get("subject", "")`）が `False` を返して承認なしにツールが走っていた。変更後は不正 JSON（#3867 で対応済み）と同様に「検査不能」として承認判定を呼ばず中断する。明示的な `"{}"` は引き続き有効。Runner と Realtime セッションの両方に影響。

### fix(chat-completions): 空で切り詰められた応答で `ModelBehaviorError` (#4513)

- PR: https://github.com/openai/openai-agents-python/pull/4513 (fixes #4510)
- 変更ファイル: `src/agents/models/openai_chatcompletions.py`, `src/agents/models/chatcmpl_stream_handler.py`

`[PR]` `finish_reason="length"` でテキスト・ツール呼び出し・refusal のいずれも無い応答は、変更前は出力アイテム 0 件の空ターンになり、エージェントループが同じトークン上限に再突入していた。変更後は非ストリーミング・ストリーミング双方で `ModelBehaviorError` を送出。`finish_reason="stop"` で空の場合は従来通り空ターン。`ResponseOutputRefusal` は合成しない（トークン枯渇はポリシー拒否ではない）。

### fix(chat-completions): 対応するコールの無い function output を拒否 (#4699)

- PR: https://github.com/openai/openai-agents-python/pull/4699
- 変更ファイル: `src/agents/models/chatcmpl_converter.py`

`[差分]` openai-python 側で Responses の `function_call_output.call_id` が optional になることを見越した変更。Chat Completions の tool メッセージは必ず対応する call を要するため、`call_id` が `None` の出力を変換しようとすると `UserError("Unpaired function outputs are supported by Responses but cannot be converted to Chat Completions tool messages. Use a Responses model ...")` を送出。Responses 経路ではそのまま保持される。ストリーミング/非ストリーミング両方。

### fix(voice): 無視されている明示クライアントオプションを拒否 (#4527)

- PR: https://github.com/openai/openai-agents-python/pull/4527
- 変更ファイル: `src/agents/voice/models/openai_model_provider.py`

`[PR]` `OpenAIVoiceModelProvider(openai_client=client, organization=..., project=...)` は変更前は受理されつつ無視されていた。変更後は `OpenAIProvider`（0.22.0 で同様の変更）と揃えて拒否する。`[差分]` `OpenAIProvider` と同じく `UserError` を送出する。
