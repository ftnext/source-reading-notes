## 比較元の決定根拠

- リリースノート末尾の **Full Changelog** リンクが `compare/rust-v0.153.0...rust-v0.154.0` を指している
- リリース履歴（`gh release list --exclude-pre-releases`）では 0.154.0 の直前の安定版は 0.153.4 (2026-09-04) で、その前に 0.153.3 / 0.153.2 / 0.153.1 / 0.153.0 (2026-09-02) がある。ただし 0.153.1〜0.153.4 は各リリースノートに「Backport」「[0.153 hotfix]」と明記された 0.153 系ホットフィックス（GPT-6-Astra 関連 6 PR）で、main 側の対応 PR（#42607, #42619, #42638, #42879 と、Astra の非同期質問ガイダンス関連の #42824 / #42836 [推測: タイトルからの対応付け]）は 0.154.0 の範囲に含まれている
- `git merge-base --is-ancestor` では rust-v0.153.x のどのタグも rust-v0.154.0 の祖先ではない（各リリースタグは main から分岐したリリースコミット `## New Features` 上に打たれるため）。0.153.0 と 0.154.0 の merge-base は `2c79ee6dac` (#42178, 2026-09-02)。`git rev-list --count rust-v0.153.0..rust-v0.154.0` は 249 コミット
- 0.153.0 側にだけある 3 コミットは、0.153.0 のリリースコミットと #42385 / #42256 のリリースブランチへの cherry-pick（同 PR は main にも別 SHA で入っており、0.154.0 の変更一覧にも載っている）
- 範囲内コミットの PR 番号（248 件）とリリースノート Changelog の PR 番号（247 件）を突合すると、**#44060 "Raise Guardian's action review limit to 200,000 bytes" だけがリリースノートに載っていないが差分には含まれる**（後述）。逆にリリースノートにあって範囲に無い PR は無い

### 2. 実験的な Worktree 対応（#42652, #43069, #43120, #43286）

- PR: https://github.com/openai/codex/pull/42652 (`codex exec`), https://github.com/openai/codex/pull/43069 (対話セッション/fork), https://github.com/openai/codex/pull/43120 (`/worktree`), https://github.com/openai/codex/pull/43286 (ブラウザ)
- 分類: **新機能（実験的、デフォルト無効）**

何が変わったか:

- `Feature::Worktrees`（設定キー `worktrees`、`Stage::Experimental`、`default_enabled: false`）を追加。`/experimental` メニューに「Worktrees — Create isolated Git worktrees and group sessions by repository.」が並び、有効化後は再起動が必要 [差分: `codex-rs/features/src/lib.rs`]。`config.schema.json` の `features` にも `worktrees: boolean` が追加
- 共通 CLI オプションに `--worktree`（"Run the session in a new managed Git worktree."）を追加。`codex exec` ではグローバル引数として `exec fork` 等のサブコマンドでも使える [差分: `codex-rs/utils/cli/src/shared_options.rs`, `codex-rs/exec/src/cli.rs`]
- worktree の置き場所は Desktop アプリと共有の `[desktop]` 設定（`worktree-root`、`worktree-keep-count`、デフォルト保持数 15）から解決し、CLI 割り当てでは自動クリーンアップを無効にする `WorktreeSettings::for_cli` を追加 [差分: `codex-rs/worktree/src/settings.rs`]
- #43069 で `codex --worktree` と `codex fork --worktree <session-id>` に対応（ローカルセッションのみ。対話型 fork では明示的なセッション指定が必須）。fork 先は `--cd` が無ければセッション最後の保存 cwd。明示的に untrusted なソースからは拒否し、起動失敗時は未バインドのチェックアウトを残して手動復旧手順を表示 [PR]
- #43120 で TUI に `/worktree` を追加。`/new` と `/fork` にも「現在のチェックアウト / 新しい worktree」の選択肢が出る（ローカル Git リポジトリかつ機能有効時）。プライマリセッションがアイドルでキュー入力が無いことが必要で、developer instructions が異なる fork は拒否 [PR]
- #43286 で `/worktree` に検索可能な「Browse worktrees」を追加。プールから一覧し、所有スレッドの resume や作業ディレクトリのコピーができる [PR]

使用例:

```toml
# ~/.codex/config.toml
[features]
worktrees = true
```

```sh
codex --worktree                # 新規 worktree で対話セッション開始
codex exec --worktree "..."     # 非対話実行を隔離チェックアウトで
codex fork --worktree <session-id>
```

利用者への影響: 機能フラグを有効にしない限り挙動は変わらない。有効にした場合、リモート実行、ephemeral セッション、`--ignore-user-config` との併用等は拒否される [PR]。CLI で作った worktree は自動削除されないため、不要になったら手動で片付ける必要がある [差分]。関連: #42196（管理 worktree 作成の基盤）、#42366（一覧）、#43279（TUI セッション探索に linked worktree を含める）、#43298 / #43376（TUI ループでの遷移タイミング調整）、#43315（セッションラベルの一意解決）。

### 3. Codex 作業中の質問にインラインで回答（#42891, #42894, #42897）

- PR: https://github.com/openai/codex/pull/42891 (+765/-34), https://github.com/openai/codex/pull/42894 (+727/-72), https://github.com/openai/codex/pull/42897 (+727/-69)
- 分類: **新機能**

何が変わったか [PR]:

- 0.153.0 の merge-base 直前に入った「構造化された非同期ユーザー入力リクエスト」(#42178) と「自由記述の非同期ユーザーメッセージ」(#42354) を TUI 側で表示・回答できるようにした
- 実行中のエージェントメッセージに含まれる質問を、折りたたまれた件数表示＋展開式の回答エディタで表示。質問間の移動、回答、キュー、スキップができ、メインコンポーザーの下書きは保持される。キーマップピッカーにも質問ナビゲーション/スキップのアクションが追加
- 回答は既存の入力配信経路を通し、送信/キューが受理されたときだけ消費。切断中は編集のみ可（配信・スキップは無効）
- #42894: 提案された選択肢を番号付きで表示し、数字キーで即決。選択肢が画面に収まらない場合は送信をブロックしてターミナル拡大を促す。選択肢は先頭 32 件まで、ラベル 512 バイト超は破棄。キー長押しによる連続回答を防ぐため送信キーのリピートを無視
- #42897: 「Other」を編集可能な選択肢として末尾に追加。入力/ペーストで開き、空欄送信は拒否。Vim 編集・検索も質問入力で使える

利用者への影響: モデルが質問ツールを使うセッション（GPT-6-Astra 系のガイダンスがこの用法を前提にしている。#42824, #42836, #42677 参照）で、作業を止めずに回答できる。旧バージョンでは質問がメッセージとして流れるだけだった [推測: #42178 以前の挙動に基づく]。

### 4. Windows でバックグラウンド Codex サーバー（デーモン）を共有・自動更新（#42405, #42392）

- PR: https://github.com/openai/codex/pull/42405 (+660/-93, 25 files), https://github.com/openai/codex/pull/42392 (+466/-87, 9 files)
- 分類: **新機能（Windows）**

何が変わったか [PR]:

- 管理された app-server デーモンと TUI の自動アタッチは Unix 限定だったのを Windows でも有効化。デーモンのライフサイクルコマンド、`codex agents` 起動、AF_UNIX によるデーモン探索が Windows で動く
- Windows デーモンは非昇格での起動を必須とし、発見したソケットディレクトリとピアを検証してから接続
- 暗黙に発見したデーモンに接続できないときは埋め込みサーバーにフォールバック。明示的なリモートエンドポイントのエラーはそのまま。`CODEX_EXEC_SERVER_URL` 設定時はデーモン再利用をバイパス
- #42392: 非対話 PowerShell インストーラで更新ループを回し、更新後に管理 app-server を再起動。インストーラの子孫プロセスは Windows Job に閉じ込め、PID 再利用時に他プロセスを誤って kill しないよう保護

利用者への影響: Windows ユーザーは複数 Codex セッションで 1 つのバックグラウンドサーバーを共有できる。Unix ユーザーへの影響は無い。関連: #42326（制御ソケットのランデブー強化）、#42364（graceful shutdown）、#42381（管理ライフサイクル）、#43308（シャットダウンファイルをソケットリクエストに置換）。

### 5. Vim `R` 置換モードと旧式ターミナルでの Esc 復元（#42194, #42584）

- PR: https://github.com/openai/codex/pull/42194 (+634/-53), https://github.com/openai/codex/pull/42584 (+365/-2)
- 分類: **新機能 / バグ修正**

何が変わったか [差分・PR]:

- Vim ノーマルモードで `R` を押すと置換モードに入り、カーソル下のグラフェムを上書き、行末では追記。Backspace で上書き前の文字を復元でき、undo と `.`（dot-repeat）にも記録される
- キーマップに `vim_normal.enter_replace_mode` が追加（`codex-rs/config/src/tui_keymap.rs`）。キーマップピッカーのアクション数は 137 → 138
- #42584: 旧式ターミナルは `Alt+文字` を `Esc` + 文字 と同じバイト列で送るため、Vim insert/replace モードで `Esc` 直後にコマンドを打つとモードがずれる問題を修正。Vim モードが Esc を消費できる場合は `Esc` と文字を別イベントとして復元。既存の Alt バインド、キーコード、画像ペースト、AltGr 等は維持

利用者への影響: Vim モードを使っている人向け。`R` を独自バインドしていた場合は `[tui.keymap.vim_normal] enter_replace_mode` で調整可能 [推測: キーマップ機構の一般則から]。

### 6. 書式を保持したコピーと `/copy` の拡張（#42847, #43055）

- PR: https://github.com/openai/codex/pull/42847 (+329/-57), https://github.com/openai/codex/pull/43055 (+367/-79)
- 分類: **新機能**

何が変わったか [PR]:

- 応答全体をネイティブクリップボードでコピーするとき、元の Markdown に加えてレンダリング済み HTML を載せる。リッチテキスト対応アプリに貼ると見出し・リスト・表・コードの書式が保持される。コードブロック・引用・トランスクリプト・ターミナル・WSL クリップボードへのコピーはプレーンテキストのまま。生 HTML はエスケープ、リモート画像ソースは除外、未対応リンク先はテキスト表示
- `/copy` は従来、最後のアシスタント応答とそのコードブロック/引用しか対象にできなかった。`/status` 実行後は、ステータス全体（プレーンテキスト）、モデル、ディレクトリのフルパス、スレッド名、セッション ID を個別にコピーできる。その後ユーザーメッセージ/応答/`/copy` 以外のコマンドが来ると通常の応答コピーに戻る。ピッカー名は "Copy to clipboard" に変更

利用者への影響: プレーンテキストのみ受け付ける貼り付け先では従来どおり Markdown テキストが入る [推測: HTML と併記のため]。

## Bug Fixes

### 7. プラグイン更新が既存セッションに反映される（#42284, #42593, #42990）

- PR: https://github.com/openai/codex/pull/42284, https://github.com/openai/codex/pull/42593, https://github.com/openai/codex/pull/42990
- 分類: **バグ修正**

変更前 [PR]: 同じ `CODEX_HOME` を共有する別プロセスがプラグインを更新/ロールバックしても、実行中プロセスのキャッシュは無効化されず、スキル一覧が古いプラグインパスを指したままだった。ローカルプラグインをインストールしても、既にロード済みのスレッドは旧設定を保持し、バンドル MCP サーバーが使えなかった。フックランタイムも通知を受けず古いフックのまま。

変更後: キャッシュされたプラグインのルートが現在のインストールと一致しなければ再ロード（#42284。設定ベースのスキルスナップショットは直近 32 件を保持）。ローカルプラグインインストール後にロード済みスレッドのユーザー設定を再読込し、その後に MCP/フックランタイムを更新（#42593。再読込失敗でもインストール自体は成功扱いでログのみ）。ターン構築時にフックソースと警告を比較して差分があれば更新（#42990）。

利用者への影響: プラグイン更新後に Codex を再起動しなくても新しいツール/スキル/フックが効く。関連: #43031（更新済み MCP ツールカタログをクライアントと一緒に保持）、#43039（`app/installed` 経由でライブスレッドのツールを更新）、#42406（MCP 起動時の明示的プラグイン mention を尊重）。

### 8. MCP 接続の OAuth トークン更新の調停とログインチャレンジの伝播（#42413, #42552）

- PR: https://github.com/openai/codex/pull/42413 (+683/-128), https://github.com/openai/codex/pull/42552 (+365/-11)
- 分類: **バグ修正**

何が変わったか [PR]:

- streamable HTTP の MCP 接続で `McpOAuthRefreshMode::Coordinated` を実装。RMCP（3.2.0 へ更新: #42383）に固定された資格情報ストア経由でトークンを更新・永続化させ、リフレッシュロックを保持しながら再読込、再試行前に永続化、login/logout の書き込みと進行中のリフレッシュを直列化。OAuth 準備は MCP 操作/ハンドシェイクのデッドライン外に置き、呼び出し元がキャンセルされても永続化は完了させる
- #42552: サイレントリフレッシュで回復できない `401 Unauthorized` は、`WWW-Authenticate` ヘッダをまとめて `mcp/www_authenticate` メタデータ付きの MCP ツールエラーに変換。リフレッシュ失敗後に拒否されたツール呼び出しを自動リプレイしない

利用者への影響: 複数セッションが同じ MCP サーバーの OAuth トークンを同時にリフレッシュしても競合しない。トークン失効時は対話的ログインを促すチャレンジが表面化する。関連: #42384（RMCP OAuth 資格情報ストアアダプタ）、#43428（opt-in の stdio MCP サーバーへ auth 変更通知）、#43289 / #43352 / #43265（実験的なユーザー検証 API）。

### 9. 信頼確立前のワークスペース制御ヘルパー実行を回避、macOS サンドボックスのターミナル入力注入をブロック（#42324, #42590）

- PR: https://github.com/openai/codex/pull/42324 (+975/-906, 19 files), https://github.com/openai/codex/pull/42590 (+142/-1, 2 files)
- 分類: **バグ修正（セキュリティ強化）**

変更前 [PR]: 自動起動処理や `codex doctor` はワークスペースが信頼される前に動くため、リポジトリが制御する `PATH` によってワークスペース提供の実行ファイルが実行され得た。また macOS のサンドボックス化コマンドはユーザーの制御端末を継承するため、`TIOCSTI` ioctl で Codex 終了後に再開する非サンドボックスシェルへ入力をキューできた。

変更後 [差分・PR]:

- 自動起動で使うヘルパーは信頼済みのシステムインストールディレクトリから解決。プラグイン同期の Git サブプロセスにはサニタイズ済み環境を渡す。ターミナル検出は環境変数のみで行い、doctor は実行ファイルの場所を実行せずに検査。更新メタデータ取得は `curl` ではなく HTTP クライアントで行う。tmux のキーボード拡張フラグ等は信頼済みヘルパーが無ければ保守的にフォールバック
- `codex sandbox`（`codex-rs/cli/src/debug_sandbox.rs`）が生成する Seatbelt ポリシーの末尾に `(deny file-ioctl (ioctl-command TIOCSTI))` を追記。macOS PTY 統合テスト `sandbox_tty.rs` でサンドボックス無しでは注入できることを確認したうえで、Seatbelt が `EPERM` で拒否することを検証

利用者への影響: 通常利用で挙動は変わらない。カスタムの `PATH` 上にある独自ヘルパー（tmux/curl 等のラッパー）に依存していた場合、起動時処理がそれを使わなくなる [推測]。

### 10. リモートの resume/fork で保存済みパーミッションを保持、サーバー側モデルデフォルトを尊重（#43330, #43177, #43355）

- PR: https://github.com/openai/codex/pull/43330, https://github.com/openai/codex/pull/43177, https://github.com/openai/codex/pull/43355
- 分類: **バグ修正**

変更前 [PR]: リモートタスクを resume/fork すると、ローカルのパーミッション設定（名前付きパーミッションプロファイル含む）がサーバーに保存された設定を上書きし得た。新規起動時は、クライアントに保存されたモデル/推論努力設定が app server の実効設定と食い違うことがあり、サーバー側でモデルがクリアされているとブートストラップ時の古いモデルで起動した。CLI fork ではクライアントのデフォルトが fork 先のモデルを上書きしたり、古いモデルに対する移行プロンプトが出た。

変更後: リモート resume/fork リクエストからパーミッション上書きを省き、セッションフラグや選択プロファイル由来の明示的な上書きは拒否。resume 後に復元されたランタイム上書きを更新し、前タスクの設定が残らないようにする（#43330）。新規起動時は `thread/start` 前に `config/read` で `model` と `model_reasoning_effort` を読み、CLI/プロファイルの明示設定は保持。サーバーにモデルが無ければモデルカタログから選ぶ。`config/read` 未対応の旧サーバーではローカルデフォルトにフォールバック（#43177）。CLI fork では暗黙のモデル/推論努力上書きを省き、移行プロンプトとサービスティア推論をスキップ（#43355）。

利用者への影響: `--model` 等を明示していれば従来どおり。明示していない場合、サーバー（デーモン/リモート）の設定が優先されるようになる。関連: #42639（保存済みモデルデフォルトが上書きされたときの警告）、#43261（バックグラウンドタスク起動でもサーバーデフォルト）、#43340（リモート名前付きパーミッションプロファイル選択）、#43359（TUI ステータスにサーバーのモデルプロバイダ ID）。

### 11. 他アプリで開いている会話の resume は読み取り専用表示＋再試行（#43253）

- PR: https://github.com/openai/codex/pull/43253 (+865/-105, 29 files)
- 分類: **バグ修正（UX）**

変更前: 別アプリ（Desktop 等）で開いている会話を resume すると active-writer エラーで失敗した。変更後 [PR]: 起動時およびセッション選択時に active-writer 衝突が起きたら読み取り専用の履歴スナップショットにフォールバック。コンポーザーは説明通知に置き換わり、`R` で再試行、終了ショートカット、トランスクリプト表示ショートカットが使える。入力はブロックされ、実行中コマンド/MCP アニメーションは停止。初期プロンプトと既存の下書きは再試行成功時のために保持され、同一スレッドの再試行ではサブスクリプションを維持。

### 12. 自動承認レビュー（Guardian）の認可コンテキスト保持と古い承認の拒否（#42844, #42852, #43442）

- PR: https://github.com/openai/codex/pull/42844 (+663/-140), https://github.com/openai/codex/pull/42852 (+598/-104), https://github.com/openai/codex/pull/43442 (+369/-13)
- 分類: **バグ修正（安全性）**

背景: Guardian は、コマンド実行等の承認を別モデルが自動レビューする仕組み（主に `GuardianThreadContext` / `guardianv2` 設定配下、#43104）。コンテキスト圧縮（compaction）でユーザーの元指示が会話ウィンドウから消えると、レビューが認可根拠を失う問題があった。

変更後 [PR]:

- ホスト側で保持するコンテキストにユーザーメッセージ全文を取り込み、検証済み回答と並べて順序付きの認可証拠として提供。大きすぎる指示は部分的に見せず丸ごと省いて「証拠不完全」通知を出す。fork した子エージェントに継承されたユーザーメッセージは、モデルには見えるが子ローカルの認可にはならないようマーク（#42844）
- 大きすぎるルートユーザーメッセージは有界の抜粋を compaction/resume/rollback をまたいで保持。レビューセッションと非同期スコアリングは、互換性のあるレビューモデルが生成した非空チェックポイントだけ再利用し、再利用不可・互換性不明・内容不良ならレビューせず fail closed（#42852）
- チェックポイント選択とプロンプト証拠に同じ親履歴スナップショットを使い、並行 compaction による証拠消失を防ぐ。レビュー中に新しいユーザー指示/回答が来てユーザーメッセージのリビジョンやルート認可バージョンが変わったら、完了済みの allow 判定をキャンセル（#43442）

利用者への影響: Guardian を使う構成でのみ影響。自動承認がより保守的になり、条件によっては拒否や手動承認への差し戻しが増える可能性がある [推測]。Guardian 関連の他 PR は末尾参照。
