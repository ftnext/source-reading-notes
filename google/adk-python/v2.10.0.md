## 全体の要点

1. **スキル（SkillToolset）のライフサイクル管理**が大幅拡充（実験的・デフォルト無効、`ADK_ENABLE_SKILL_LIFECYCLE=1` で有効化）。`SkillLifecycleConfig` による PERSISTENT / BOUNDED / EPHEMERAL のモード、`max_active_skills` 上限、`unload_skill` ツール、アンロード済みスキルの指示文をリクエストから落とす処理、スキル変更の再検証 (`revalidate_skills`)。加えてフラグ不要の `SkillDiscoveryMode`（LAZY / EAGER）、プログラム的な `load_skill` / `unload_skill` API、`run_skill_script` の自動非表示。
2. **MongoDB ツールセット**（`google.adk.integrations.mongodb.MongoDbToolset`、extra `google-adk[mongodb]`）新設。Atlas Vector Search と `$rankFusion` によるハイブリッド検索。
3. **評価 (eval) の効率メトリクス**追加：トークン数・モデル呼び出し回数・所要時間を情報メトリクスとして計測。
4. **OpenAI モデル連携の大幅強化と昇格**：`google.adk.labs.openai` → `google.adk.integrations.openai` へ移動（旧パスは再エクスポートで互換維持）、extra `google-adk[openai]` 追加、推論モデル向けのリクエストパラメータ自動調整、`OpenAIGenerateContentConfig.effort`、reasoning トークン報告、ストリーミング usage / finish_reason、`api_key` のコーラブル対応、`base_url`。
5. **Gemini の Interactions API サービスティア**：`RunConfig.service_tier`（`ServiceTier.FLEX / STANDARD / PRIORITY / DEFERRED`）。DEFERRED は非同期オペレーションを待ち合わせる。
6. **挙動変更**（リリースノートの Behavior changes）：
   - BigQuery 保護書き込みモードが、dry run で宛先を特定できない非 SELECT 文（スクリプト、`CALL`、`EXPORT DATA` など）を拒否する
   - BigQuery 保護モードの BigQuery セッション情報をセッション state ではなくプロセスメモリに保持（再起動・別レプリカに引き継がれない）
   - `OpenAIResponsesLlm` が `thinking_config` を警告付きで無視（`OpenAIGenerateContentConfig.effort` を使う）
   - `AgentEvaluator.evaluate` / `evaluate_eval_set` が評価ケース 0 件で `ValueError`
   - 指示文テンプレートで `${var}` と `\{var}` を state から埋めなくなった
   - `google.adk.flows.llm_flows.{audio_cache_manager,audio_transcriber,transcription_manager}` の import で `DeprecationWarning`
   - （All changes 内で BREAKING CHANGE と明記）`validate_path_segment` がスラッシュを含むパスセグメントも拒否
   - `LoadArtifactsTool` が `list_artifact_keys` に列挙されたアーティファクトだけをロードする（カスタム `BaseArtifactService` 実装者に影響）
   - 生成 Dockerfile の `CMD` が exec 形式になり、デプロイフラグ値中の `$VAR` がシェル展開されなくなる
7. **セキュリティ寄りの修正**が引き続き多い：OAuth2 `client_secret` をセッション state に保存しない、MCP ツール説明文のフェンシング（プロンプトインジェクション対策）、モデルの private reasoning 中のコードを実行しない、ADC を https のみに付与、アーティファクト参照の循環防止、エージェントビルダーの glob をディレクトリ内に限定、署名付き URI / HTTP options のログ redaction。
8. 依存関係：`mcp>=1.24,<3`（MCP SDK 2.x を許容。v2.9.0 では `<2` に戻されていた）、`google-cloud-aiplatform[evaluation]<2` の上限追加、新 extra `mongodb` / `openai`。

## 各変更項目の解説

### A. Highlights / Behavior changes

#### A-1. スキルのライフサイクル管理（BOUNDED / EPHEMERAL / unload_skill 等）【新機能・実験的・デフォルト無効】

- コミット:
  - モード＋上限: https://github.com/google/adk-python/commit/43b73e4fc0920c08693bcec3985c832c7d9870b0
  - EPHEMERAL: https://github.com/google/adk-python/commit/f938abd8beb213774eda069dd2a315fe998c399e
  - `unload_skill` ツール: https://github.com/google/adk-python/commit/ce53a36c0a221542afbd22dc4f3d6f5e3c8fecd7
  - アンロード済みスキルの指示文を落とす: https://github.com/google/adk-python/commit/accb906eac1534e4cc8ba66a7b2d5a389996522b
  - スキル変更の再検証: https://github.com/google/adk-python/commit/f848b7e3bd4943d245b324fd233483c9857804cf
- 実装: https://github.com/google/adk-python/blob/v2.10.0/src/google/adk/tools/skill_toolset.py
- ガイド: https://github.com/google/adk-python/blob/v2.10.0/docs/guides/skills/skill/index.md

**何が変わったか** `[差分]`

- 従来はセッション中に一度 `load_skill` されたスキルはセッション終了まで active のままで、その `adk_additional_tools` が以降の全リクエストで宣言され続けていた（長いセッションで不要なツール宣言が蓄積）。
- `SkillLifecycleMode` と `SkillLifecycleConfig`（`enabled`, `default_mode`, `max_active_skills`, `skill_overrides`, `revalidate_skills`）を `SkillToolset(lifecycle_config=...)` で渡せる。
  - `PERSISTENT`（デフォルト）: 従来どおり。上限にもカウントされず退避もされない。
  - `BOUNDED`: active な BOUNDED スキルが `max_active_skills` を超えると、最も古くロードされたものから解放される（再ロードは「使用」とみなす）。`load_skill` の応答に `unloaded_skills` が含まれ、モデルにツールが消えることが伝わる。
  - `EPHEMERAL`: ロードされたターンのみ active（そのターン内の全モデルステップで有効）で、次ターンから解放。上限にはカウントしない。ロードされたターンは `_adk_skill_meta_<agent>` state に記録される。
- `unload_skill` ツール（opt-in）: `_adk_activated_skill_<agent>` から名前を取り除く。state のみを読み書きするので、レジストリから消えたスキルにも使える。
- アンロード済みスキルの `load_skill` レスポンスは、**送信リクエスト内でのみ**「アンロードされた」旨の短い通知に書き換えられる（セッションのイベント自体は変更しない。呼び出しがオーファンにならないようドロップではなく書き換え）。
- `revalidate_skills=True`: ロード時にスキルのダイジェスト（指示文・frontmatter・全リソース）を記録し、毎リクエストで現在の定義と比較。変わっていればリクエスト内で再提示し、リソースも環境に書き直す。デフォルト off（毎ターンのレジストリ参照コストとプロンプトキャッシュ無効化があるため）。
- フィーチャーフラグ `SKILL_LIFECYCLE` は `FeatureStage.EXPERIMENTAL, default_on=False`（`_feature_registry.py`）。有効化は環境変数 `ADK_ENABLE_SKILL_LIFECYCLE=1`。

**利用者への影響**: オプトインしない限り挙動は変わらない。長時間セッションでツール宣言の肥大を抑えたい場合に有効。

#### A-2. MongoDB ツールセット【新機能・実験的（default_on=True）】

- コミット: https://github.com/google/adk-python/commit/0961ced3e3dd92056ecf10c7b10aa736eead08f1 （PR: https://github.com/google/adk-python/pull/7041 ）
- ガイド: https://github.com/google/adk-python/blob/v2.10.0/docs/guides/integrations/mongodb/mongodb_toolset/index.md
- 実装: https://github.com/google/adk-python/tree/v2.10.0/src/google/adk/integrations/mongodb

**何が変わったか** `[差分]`: `google.adk.integrations.mongodb.MongoDbToolset` を追加。`vector_search` と `hybrid_search`（`$rankFusion`）ツールが `query: str` を受け取り、内部で埋め込みを計算する。`pyproject.toml` に extra `mongodb = ["pymongo>=4.9,<5"]` と `all` への追加。フィーチャーフラグ `MONGODB_TOOLSET` / `MONGODB_TOOL_SETTINGS` は EXPERIMENTAL だが default_on=True。

**利用者への影響**: 新規追加のみ。`pip install "google-adk[mongodb]"` で利用。

#### A-3. 評価の効率メトリクス（tokens / calls / duration）【新機能】

- コミット: https://github.com/google/adk-python/commit/2d428ead3860fbc131de362b485eb15551373665 、 https://github.com/google/adk-python/commit/49e7264bf6a72a6b42813300a2192e0898ff5b23
- ガイド: https://github.com/google/adk-python/blob/v2.10.0/docs/guides/evaluation/efficiency_evaluators/index.md
- サンプル: https://github.com/google/adk-python/tree/v2.10.0/contributing/samples/evaluation/efficiency_metrics

**何が変わったか** `[差分]`: `_efficiency_evaluators.py` を追加し、トークン消費・モデル呼び出し回数・所要時間を「情報メトリクス」として eval 結果に含める。`eval_case.py` / `eval_config.py` / `eval_metrics.py` / `evaluation_generator.py` / `local_eval_service.py` / `metric_evaluator_registry.py` / `cli_eval.py`（表示）/ `dev_server.py`（API）まで一貫して拡張。`telemetry/_token_usage.py` も変更。

**利用者への影響**: eval_config にメトリクスを追加すれば計測できる。既存メトリクスの pass/fail 判定には影響しない `[推測: 「informational」と明記されているため]`。

#### A-4. OpenAI 推論モデル対応の強化【新機能】

- 推論トークン報告 + ライブテスト: https://github.com/google/adk-python/commit/52a2f0f09f2910043127042e6ba3dd805d5a1479
- 推論モデルのパラメータ自動調整: https://github.com/google/adk-python/commit/137eba8431e4e66bc469ddf6c6b8f6c38b56cc52
- `OpenAIGenerateContentConfig` と `effort`: https://github.com/google/adk-python/commit/bb9023d1fae8bf2d273f47281570a23732a7e128
- Responses API で `build_reasoning_effort` を使用（**挙動変更**）: https://github.com/google/adk-python/commit/b3d1392a1a9caf382b9483c5fecd4b9140949abb

**何が変わったか** `[差分]`

- `_openai_common.is_reasoning_model` で推論モデルを判定し、Chat Completions では `max_completion_tokens` を送って非デフォルトの `temperature` / `top_p` を落とす。Responses でも `temperature` / `top_p` を落とす。非推論モデルは影響なし。
- `OpenAIGenerateContentConfig`（`GenerateContentConfig` のサブクラス）に `effort` フィールドを追加。`supported_efforts(model, api)` / `build_reasoning_effort(config, model, api, validate=True)` でモデル・API サーフェスごとに許容される effort を検証。
- `OpenAILlm` が reasoning トークンを `thoughts_token_count` として報告。
- **挙動変更**: `OpenAIResponsesLlm` は従来 `thinking_config`（`thinking_level` / `thinking_budget`）を独自にマッピングしていたが、共有の `build_reasoning_effort` に置き換え、`thinking_config` は**警告付きで無視**される。

**移行注意点**: `OpenAIResponsesLlm` で `thinking_config` を使っていた場合、`generate_content_config=OpenAIGenerateContentConfig(effort=...)` に置き換える。

#### A-5. BigQuery 保護書き込みモードの厳格化【挙動変更・破壊的】

- コミット: https://github.com/google/adk-python/commit/8b883d07147f62f8e9979ec8e6b1205437d60f4f
- 実装: https://github.com/google/adk-python/blob/v2.10.0/src/google/adk/integrations/bigquery/query_tool.py

**変更前** `[差分]`: 保護書き込みモードは、dry run が「セッションの匿名データセット以外」を宛先と判断した非 SELECT 文だけを拒否していた。そのため、複数文スクリプト、プロシージャ呼び出し、`EXPORT DATA` など dry run が宛先を返さない文は、匿名データセット外へ書けるにもかかわらずチェックなしで実行されていた。

**変更後**: dry run が匿名データセットに宛先を置いた非 SELECT 文だけを実行する。宛先なしの文は拒否。

**利用者への影響**: コミット本文で「breaking for callers whose writes the dry run attributes to no destination」と明記。保護モードでスクリプトや `CALL` を実行していた場合は失敗するようになる。

#### A-6. BigQuery / sandbox のセッション情報をプロセス内に保持【挙動変更】

- コミット: https://github.com/google/adk-python/commit/094012b4509fc136083e6be95f273ad1163fbf2c

**変更前** `[差分]`: BigQuery セッション ID と匿名データセット ID を `tool_context.state[BIGQUERY_SESSION_INFO_KEY]` に保存していた。state は呼び出し側から書き換え可能なため、他人のために作られた BigQuery セッションでクエリが走る／保護モードが受け入れる書き込み先を差し替えられる余地があった。

**変更後**: `(app_name, user_id, session_id)` をキーとするプロセス内 `OrderedDict`（最大 1024 エントリ、ロック付き）で保持。`BIGQUERY_SESSION_INFO_KEY` は残るが読み書きされない。`vmaas/sandbox_computer.py` も同様。

**利用者への影響**: 一時テーブルは再起動や別レプリカには引き継がれない（毎回新しい BigQuery セッションが作られる）。

#### A-7. `AgentEvaluator` が 0 件評価で `ValueError`【挙動変更】

- コミット: https://github.com/google/adk-python/commit/9dbc2aebd7a0ad88183d166c19398bbbab93d507 （PR: https://github.com/google/adk-python/pull/6952 、Issue: https://github.com/google/adk-python/issues/6951 ）
- `evaluate` / `evaluate_eval_set` が、空の eval set や `*.test.json` が見つからない場合に静かに pass せず `ValueError` を送出。`num_runs >= 1` も事前検証。テストが「何も評価せずに通る」偽陽性を防ぐ。

#### A-8. 指示文テンプレートで `${var}` / `\{var}` を展開しない【挙動変更・バグ修正】

- コミット: https://github.com/google/adk-python/commit/0caecd236f95131da625a3bf1de282130f6aa437 （Issue: https://github.com/google/adk-python/issues/5706 ）
- `[差分]` `_instructions_utils.py` の正規表現を `r'{+[^{}]*}+'` → `r'(?<![\$\{\\]){+[^{}]*}+'` に変更（直前が `$`, `{`, `\` の場合はマッチしない）。
- **利用者への影響**: 指示文中にシェル風の `${VAR}` やエスケープ `\{x}` を書いていた場合、これまで state で置換（または未定義キーでエラー）されていたものがそのまま残る。逆に `${var}` で state 参照する意図だった場合は `{var}` に直す。

#### A-9. 旧 live 音声モジュールの import で `DeprecationWarning`【非推奨化】

- コミット: https://github.com/google/adk-python/commit/bf2bc561ef9c2b9cfaec5bc6ca441b6c1d3b3496
- `google.adk.flows.llm_flows.audio_cache_manager` / `audio_transcriber` / `transcription_manager` は `google.adk.live` への互換シムとして残るが、import 時に `warnings.warn(..., DeprecationWarning, stacklevel=2)` を出す。
- **利用者への影響**: `pytest -W error` のようにWarning をエラーにしているテストは失敗する。`google.adk.live` 配下（`google.adk.live._audio_cache_manager` 等、警告文に記載）へ移行する。

### B. 新機能（Features）

#### B-1. スキル関連（A-1 以外）

- **`SkillDiscoveryMode`** https://github.com/google/adk-python/commit/3d3c1d90c89128d721569f54115be2b1d0ac5a74 （PR: https://github.com/google/adk-python/pull/7093 、Issue: https://github.com/google/adk-python/issues/7092 ）
  - `LAZY`（デフォルト）: 従来どおり `list_skills` ツールを提供。`EAGER`: `list_skills` を省き、カタログを `<available_skills>` XML としてシステム指示に注入し、モデルが即 `load_skill` できる（小さな静的スキルセットで発見ターンのレイテンシ・トークンを削減）。
  - **非推奨化**: `tool_filter` で `list_skills` を隠すことでプロンプト注入を誘発する使い方は非推奨。`discovery_mode=SkillDiscoveryMode.EAGER` を使う。
- **プログラム的なスキル活性化 API** https://github.com/google/adk-python/commit/a0f395570461f2eccfecb132c6c751064b1e6bbe : `SkillToolset.list_active_skills` / `load_skill` / `unload_skill` を追加。ツールと同じ state を操作する。`load_skill` は存在しない名前で例外。活性化はスキルの指示文を会話に入れないので、ツールの使い方は自前で指示する必要がある。
