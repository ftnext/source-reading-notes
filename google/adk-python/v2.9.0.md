## 全体の要点

1. **FallbackModel**（`google.adk.models.FallbackModel`）の新設。プライマリモデルが 429/5xx を返したときにバックアップモデルへ自動フェイルオーバーする `BaseLlm` ラッパー。実験的機能だがデフォルト有効。
2. **LiveKit 連携**（`google.adk.integrations.livekit.LiveKitRunner`、extra `google-adk[livekit]`）。WebRTC / SIP 電話経由の音声エージェントを、既存の `Runner` を改変せずに LiveKit ルームへ接続する。
3. **YAML から ADK 2.0 グラフワークフロー（`Workflow`/`FunctionNode`）を構築**できるようになった（`config_agent_utils.from_config`、`adk run/web` の `root_agent.yaml`）。
4. **MCP SDK 2.x 対応**。コードは 1.x/2.x 両対応になったが、依存ピンは `mcp>=1.24,<2` に戻され、**pip install ではデフォルトで 1.x が解決される**。2.x を使うには明示的にインストールする（オプトイン）。
5. **破壊的変更**は 3 件（＋既定構成では影響しない 2 件）：
   - ワークフローの再開時、**失敗したノードは再実行される**（以前は完了扱いでリプレイ）
   - **GCS ツールのローカルファイルアクセス**は `local_file_root` 配下に限定、未設定なら拒否
   - `InMemorySessionService.append_event` が未知セッションで **`SessionNotFoundError` を送出**（以前は警告のみ）
   - （`retry_config` 設定済みノード限定）ネストしたワークフロー内部の失敗が親ワークフローのリトライを起動
   - （MCP 2.x を意図的に入れた場合限定）サーバーが送る未宣言フィールドが届かなくなる
6. その他、**セキュリティ寄りの修正**が多い：OAuth client_secret をクライアントへ流さない、A2A エージェントカード URL に https 必須、ADC トークンを Google API ホスト以外へ付けない、`adk deploy` の `app_name` を検証（Dockerfile インジェクション防止）、エージェント転送先を宣言済みターゲットに限定、など。
7. **`adk deploy` の再設計**：`adk deploy docker` 追加、Deployer 抽象（Cloud Run / Docker）、`--env` / `--provider-args`。
8. テレメトリ：Google Cloud ログ出力が OTLP（telemetry.googleapis.com）経由に変更（Agent Engine 上のデフォルトログ名が変わる、`GOOGLE_CLOUD_DEFAULT_LOG_NAME` 廃止）。

## 各変更項目の解説

### A. Highlights / 新機能（Features）

#### A-1. FallbackModel: モデル間の自動フェイルオーバー【新機能・実験的】

- コミット: https://github.com/google/adk-python/commit/c300b8ded62b8bc4168cdede4c85bec66d1aa8ee
- ガイド: https://github.com/google/adk-python/blob/v2.9.0/docs/guides/models/fallback_model/index.md
- 実装: https://github.com/google/adk-python/blob/v2.9.0/src/google/adk/models/_fallback_model.py

**何が変わったか** `[差分]`

- `FallbackModel(models=[...], retriable_status_codes=...)` が追加。`models` にはモデル名文字列または `BaseLlm` インスタンスを混在させられる。名前は `LLMRegistry.new_llm` で**初回利用時に遅延解決**される（バックアップに Claude を指定しても、使われるまで `anthropic` は import されない）。

```python
from google.adk.agents import LlmAgent
from google.adk.models import FallbackModel

agent = LlmAgent(
    name='reliable_agent',
    model=FallbackModel(models=['gemini-3.1-pro-preview', 'gemini-3.5-flash']),
    instruction='You are a helpful assistant.',
)
```

**挙動**

- 既定の `retriable_status_codes` は 429, 500, 502, 503, 504。ステータスは `google.genai` の `APIError.code`、litellm/OpenAI/Anthropic の `status_code`、`httpx` の `response.status_code` から読む。ステータスを持たないエラー（接続リセット等）はフェイルオーバーせず伝播。408 は既定に含まない。
- **各モデルは 1 回ずつ**試す。単一モデルのリトライはそのモデルの `retry_options` に任せる（二重リトライ防止）。
- **ストリーミング中に最初のレスポンスを返した後の失敗はフェイルオーバーしない**（2 モデルの出力を 1 ターンに混ぜないため）。Live 接続も同様に「接続確立まで」がフェイルオーバー対象。
- 失敗したモデルがリクエストに加えた in-place 編集（contents/config/live connect config）はロールバックされてから次のモデルへ渡る。
- 全モデル失敗時は最後のエラーが伝播（`on_model_error_callback` で拾える）。
- `ADK_DISABLE_FALLBACK_MODEL` 環境変数で無効化可能（feature registry 登録、既定有効）。

**利用者への影響** 既存コードには影響なし（オプトイン）。LiteLLM 経由なら `LiteLlm(fallbacks=[...])` が従来から存在し、`FallbackModel` はモデルクラスをまたぐ（Gemini → Claude 等）場合の選択肢。

#### A-2. LiveKit ランナー（音声・電話）【新機能・実験的】

- コミット: https://github.com/google/adk-python/commit/f277d9117781fb4e2d8cd2608a1d484c29884e60 (PR [#6846](https://github.com/google/adk-python/pull/6846))
- README: https://github.com/google/adk-python/blob/v2.9.0/src/google/adk/integrations/livekit/README.md
- サンプル: https://github.com/google/adk-python/tree/v2.9.0/contributing/samples/integrations/livekit

**何が変わったか** `[差分]`

- 新パッケージ `google.adk.integrations.livekit`（`LiveKitRunner`, `LiveKitToolset`, 通話操作ツール群、transcripts）と extra `google-adk[livekit]`（`livekit>=1,<2`, `livekit-api>=1,<2`, `pillow>=10.3`）。
- `LiveKitRunner(runner=..., room=<接続済み rtc.Room>, user_id=..., session_id=...).start()` で、既存の `Runner` を **`LiveRequestQueue → run_live() → Event`** の契約を通じて LiveKit ルームにブリッジする。エージェント側コードの変更は不要。
- 出力は LiveKit 標準チャネル（音声トラック、`lk.transcription`、`lk.chat`、`lk.agent.state` 属性）に流れるため、LiveKit のクライアント SDK / プレビルト UI がそのまま使える。ツール呼び出しは独自の `adk` データトピックに JSON で出る。
- 入力はマイクトラック、`lk.chat`、カメラトラック（1 fps で JPEG 化してモデルへ）。
- セッションが無ければ作成（`create_session=False` で無効化）。参加者を最大 30 秒待つ（`wait_for_participant`）。
- `livekit-agents>=1.4` のワーカー（`@server.rtc_session`）からのディスパッチにも対応し、`user_id`/`session_id` はジョブメタデータで渡す。

**利用者への影響** 新規オプトイン。constraints ファイルにも依存が追加された。

#### A-3. YAML 設定から ADK 2.0 グラフワークフローを読み込む【新機能】

- コミット: https://github.com/google/adk-python/commit/2a9461b1da1c3f7bf732cb37ac43a865f907c6a4
- ガイド: https://github.com/google/adk-python/blob/v2.9.0/docs/guides/agents/config/index.md
- 実装: `src/google/adk/agents/config_agent_utils.py`（+282 行）

**何が変わったか** `[差分]`

- `agent_class: Workflow` の YAML を `config_agent_utils.from_config()` で読めるようになった。`edges` は「チェーン（ブロック形式リスト）」「ルーティングマップ（route 名 → ノード）」「明示的 `from_node`/`to_node`/`route`」の 3 形式。ノードは `START`、同ファイル内の名前、相対 `.yaml` パス、関数参照（`FunctionNode` にラップ）、インラインマッピングで指定できる。
- ノードは名前と参照でキャッシュされ、チェーンで一度出したノードを後続エッジで再利用できる（`START` や共有サブグラフの同一性が保たれる）。
- ディレクトリに `__init__.py`/`agent.py` が無く `root_agent.yaml` がある場合、`adk run` / `adk web` / `adk api_server` はそれを読む。

```yaml
agent_class: Workflow
name: my_sample_workflow
edges:
  - - START
    - my_module.functions.process_data
    - sub_agent.yaml
```

**注意** ルーティングマップで単一キー `code` 文字列値のマップはエージェント参照と解釈されるため、その形のルートは使えない。前提として、直前の内部リファクタ「map YAML agent configs onto agent classes by reflection」（リリースノート非掲載）の上に構築されている。

#### A-4. MCP SDK 2.x を 1.x と併せてサポート【新機能＋条件付き破壊的変更】

- コミット: https://github.com/google/adk-python/commit/856acf21e3155d2145f9af0709434dd46843539c
- ピン戻し: https://github.com/google/adk-python/commit/46edaa24a4ee1e14b542638950d3043096a56032（fix(mcp): keep resolving MCP 1.x by default）

**何が変わったか** `[差分]`

- `google.adk.dependencies._mcp` の seam が、2.0 でリネームされたシンボル（`McpError`→`MCPError`、`mcp.server.fastmcp.FastMCP`→`mcp.server.mcpserver.MCPServer`）を import 時に解決。HTTP クライアントライブラリも **インストール済み SDK のメジャーに応じて `httpx` / `httpx2` を選択**（`dependencies/_httpx.py` 新設）。
- `ClientSession(read_timeout_seconds=...)` の型（1.x は `timedelta`、2.x は `float`）を seam が公開し、変換点が読む。
- `McpTool` / `McpToolset.get_resource_info` の dump はメジャーでゲートした共通ヘルパーに統一。2.x では by_alias で dump して 1.x の camelCase 綴り（`isError`, `structuredContent`, `mimeType`）に揃え、`_meta` は各階層で戻す。**1.x では従来と完全に同じ dump 呼び出し**になる。
- MCP Apps ウィジェットのペイロード `payload["tool"]` は model ではなく dict になった（シリアライズ後の形は元から dict）。
- `load_mcp_resource_tool` が `mimeType`/`mime_type` の両綴りを読むようになった（2.x でバイナリリソースがすべて「デコード不能」に見えていた潜在バグの修正）。
- 一度 `mcp>=1.24,<3` に広げられたが、直後の 46edaa2 で `all`/`mcp`/`test` extras とも **`mcp>=1.24,<2` に戻された**。つまり本リリースを普通にインストールすると 1.x が入る。2.x は `pip install "mcp>=2"` 等で明示的に上書きした場合のみ。

**MCP 2.x を入れた場合の破壊的変更（1.x では変化なし）**

- 2.x はモデルが closed（`extra="forbid"` 相当）なので、サーバーが送る**未宣言フィールドは `CallToolResult` や `raw_mcp_tool` に届く前に破棄**される。`_meta` は宣言済みなので届く。ベンダー拡張は `_meta` 下に移すべき。
- 公開面の HTTP クライアント型が `httpx2` になる。自前の `httpx_client_factory` / `mtls_transport` を `httpx` で組んでいると SDK のトランスポートが使えない。
- `McpToolset.read_resource` は SDK のモデルをそのまま返すので、フィールド綴りは `mime_type` になる。
- `Resource.uri` が `AnyUrl`→`str` になり、`get_resource_info()["uri"]` が `file://report.json/`（1.x 正規化）ではなく `file://report.json`（宣言通り）になる。
- OpenTelemetry httpx インストルメンタは `httpx2` 非対応のため、2.x では MCP の HTTP 呼び出しがトレースされない（壊れるのではなく未計測）。
- CI に MCP 2.x 用のジョブが追加された（`.github/workflows/continuous-integration.yml`）。

### B. 破壊的変更（Breaking changes）

#### B-1. ワークフロー再開時、失敗したノードを再実行する

- コミット: https://github.com/google/adk-python/commit/c274ac347ab91ed523a1da6fee3ec7d9fdb9ff8c （`fix!: rerun a failed node on resume instead of replaying it as complete`。リリースノートの「All changes」にはハッシュ無しで掲載）

**変更前** セッション再開（cross-turn）時、`_replay_interceptor.check_interception` は「出力・ルート・転送のいずれもなく、割り込みもない」ノードを「完了済み」とみなしてファストフォワードしていた。失敗したノードはイベントに `error_code` を残すだけで出力が無いため、**完了扱いで空出力のままリプレイ**されていた。

**変更後** `[差分]` `_rehydration_utils._ChildScanState` に `error_code` を追加し、最新の試行が結果（出力/ルート/転送）を持てばエラーをクリア、持たず `error_code` があれば保持。`check_interception` に新ケース「Case 3: 前ターンで失敗」を追加し、`should_run = True` で**ノードを再実行**する。

**利用者への影響** 外部副作用を起こした後に失敗するノードは、**再開ごとに副作用を繰り返す**。ノード本体を冪等にすること。

#### B-2. GCS ツールのローカルパスを `local_file_root` 配下に限定

- コミット: https://github.com/google/adk-python/commit/6f2ee9280abd5a1ebb0d35afbaf382b979d58982 （`fix!: confine GCS tool local file paths to a configured root`）
- 追補: https://github.com/google/adk-python/commit/48b28deeb8d3d761ffff5b7ce51300142d5cbff3 （`fix(gcs): judge a local path by where it lands, not by whether it is absolute`）

**変更前** `create_object(source_file_path=...)` / `get_object_data(destination_file_path=...)` はモデルが指定した任意のローカルパスをそのまま読み書きしていた。

**変更後** `[差分]`
- `GCSToolSettings.local_file_root: str | None = None` を追加。
- 新ヘルパー `_resolve_local_path` が、root 未設定なら `ValueError("Local file access is disabled. ...")`、シンボリックリンク解決後に root 外へ出るなら `"Local file path escapes the configured root"`、root そのものを指すなら拒否。ダウンロード時は親ディレクトリを自動作成。
- 6f2ee92 時点では絶対パスを一律拒否していたが、48b28de で**絶対パスも許可し、解決先が root 内かどうかで判定**するよう修正（エラーメッセージに root を含めない）。
- サンプル `contributing/samples/integrations/gcs/agent.py` も `local_file_root` を設定する形に更新。

**利用者への影響** GCS ツールでローカルファイルのアップロード/ダウンロードを使っていた場合、**`local_file_root` を設定しないと全て失敗**する。パスは相対でも絶対でもよいが root 内に収まる必要がある。

#### B-3. `InMemorySessionService.append_event` が未知セッションで `SessionNotFoundError`

- コミット: https://github.com/google/adk-python/commit/c8bc126fd98e7fe062abce3fd62ac2bd3e96aebc （`fix!: raise SessionNotFoundError when appending to an unknown session`）

**変更前** app_name / user_id / session_id が見つからない場合 `logger.warning` を出してイベントを返す（保存はしない）。

**変更後** `[差分]` `raise SessionNotFoundError(f'Session {session_id} not found.')`。`DatabaseSessionService` 等は既にこの挙動だったため、全バックエンドで統一。ガイド `docs/guides/sessions/session/index.md` の「バックエンドごとに失敗の仕方が異なる」注記が削除された。

**利用者への影響** インメモリセッションのみ。削除済み/未作成セッションへの append がテストなどで暗黙に通っていた場合は例外になる。

#### B-4. ネストしたワークフローの内部ノード失敗で親をリトライ（`retry_config` 設定済みノード限定）

- コミット: https://github.com/google/adk-python/commit/dcdd9b8a72f6ef35f695b456c665e261e9df11ce （`fix!: retry a nested workflow when a node inside it fails`）
- ガイド: https://github.com/google/adk-python/blob/v2.9.0/docs/guides/workflow/retry_config/index.md

**変更前** `Workflow` は子ノードの失敗を例外ではなく自身の `ctx.error` に設定して報告するため、`NodeRunner` の `except` ブロックに到達せず、`Workflow` に付けた `retry_config` が**内部ノードの失敗では発火しなかった**。

**変更後** `[差分]` `NodeRunner.run` が `_execute_node` 後に `ctx.error` を確認し、`_attempt_retry` が真なら再試行する。リトライ時、既に出力または state 変更を残した子はイベントからリプレイされ、**出力も state 変更も残さなかった子は毎回再実行**される。

**利用者への影響** `Workflow` ノードに `retry_config` を設定している場合のみ挙動が変わる。副作用のある子ノードには出力か state 変更を持たせること。

A-4 を参照。本リリースの依存解決では 2.x は入らないため、既定構成では影響しない。

## 移行チェックリスト（v2.8.0 → v2.9.0）

1. ADK 2.0 ワークフローで、外部副作用を持つノードが失敗し得る場合、**再開時に再実行される**ことを前提に冪等化する（B-1）。`Workflow` に `retry_config` を付けている場合は B-4 も確認。
2. GCS ツールでローカルファイルを扱うなら `GCSToolSettings(local_file_root=...)` を設定する（B-2）。
3. `InMemorySessionService.append_event` を未知セッションに対して呼ぶコード/テストがあれば `SessionNotFoundError` を処理する（B-3）。
4. `RestApiTool` で `httpx.TimeoutException` を捕まえていたら、返却されるエラー dict を見る形に変える（C-7）。
5. `ParallelAgent` の `ExceptionGroup` を捕まえていたら、個別の例外型に変える（C-4）。
6. `LoopAgent(max_iterations=0)` を「無制限」の意味で使っていたら `None` にする（C-4）。
7. 複数の `before/after_tool_callback` を登録している場合、最初の非 None で連鎖が止まる（C-4）。
8. リモート A2A エージェントカードを http の非ローカルホストで参照していたら https にする（C-1）。
9. 非 Google ホストの MCP サーバーで ADC トークン付与に依存していたら、明示的な認証を設定する（C-2）。
10. Agent Engine 上で Cloud Logging のログ名 `adk-on-agent-engine` や `GOOGLE_CLOUD_DEFAULT_LOG_NAME` に依存していたら見直す（A-5 telemetry）。
11. Spanner extras を使う場合 `google-cloud-spanner>=3.64` に更新（C-7）。
12. MCP 2.x を試す場合は A-4 の非互換点を確認。通常インストールでは 1.x のまま。
