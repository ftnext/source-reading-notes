## 全体の要点

1. **実行キャンセル（abort_signal）**: `Runner.run_async(..., abort_signal=asyncio.Event())` で実行中のエージェント／ワークフローを停止できる。中断時は応答のない function call に合成エラー応答（`error_code="INVOCATION_ABORTED"`）を書き込み、`/run_sse` はクライアント切断で自動的に中断する。
2. **ワークフローのツールノードがエージェント内ツールと同じ振る舞いに**: ツール確認（`RequestInput` で一時停止）、プラグインの tool コールバック、`artifact_delta` などのアクション伝搬、`skip_summarization`。
3. **ModelConsultTool**: 小さな実行モデルが途中で強いアドバイザーモデルに相談するツール（ターン／セッション単位の回数上限つき）。
4. **SQLite メモリサービス**: `SqliteMemoryService`、`--memory_service_uri sqlite://...`。FTS5（なければ LIKE）で検索。
5. **MCP SDK 2.x のモダンプロトコル接続**（`ADK_ENABLE_MCP_MODERN_PROTOCOL=1` でオプトイン）と、SDK 2.x でのセッション死活判定・キャンセル時処理の修正。
6. **破壊的変更**: dev UI の `runtime-config.json` をインストール済みパッケージに書き込まず、サーバーがリクエストごとに返すようになった。
7. **リリースノートでは feat / fix 扱いだが挙動が変わるもの**（移行時に注意）:
   - ツールノード内の確認必須ツールがプレースホルダーのエラーを流さず一時停止する（`ce132b9`）
   - App のプラグインの tool コールバックがツールノードにも適用される（`cfeece9`）
   - `NodeTool` 内のノード失敗が例外として伝播し、`on_tool_error` がなければ実行が失敗する（`b4c5272`）
   - 中断後の再開でぶら下がったツールが再実行されなくなる（`da65851`）
   - `Runner.run_async` の `new_message` は role に関係なくユーザーターンとして保存（`15ec279`）
   - Jinja2 指示文テンプレートがサンドボックスで描画される（`0e19550`）
   - DB セッションの `update_time` が更新時に自動で `now()` にならない（`aec7c0a`）
   - スキルのテレメトリ属性名が `adk.experimental.skill.*` から `gen_ai.skill.*` / `adk.skill.*` へ（`e0f4c97`）
   - `db` extra が `sqlalchemy[asyncio]`（greenlet 込み）を入れる（`ffc2494`）
8. **セキュリティ寄りの修正**: `load_web_page` のプロキシ経路の SSRF 対策、RestApiTool のパストラバーサル対策、Jinja2 サンドボックス化、圧縮プロンプトへの認証情報混入防止、AgentRegistry の pickle にデプロイ者の認証情報が入る問題、ToolCallIntegrityPlugin（HMAC による tool call 改ざん検知）の追加。

## 破壊的変更（Breaking changes）

### dev UI のランタイム設定をファイルではなくサーバーから配信する

- コミット: [3722746](https://github.com/google/adk-python/commit/3722746568a33226d54ba51876801c5948479eb5)（`refactor!:`）
- 変更前: `adk web` などの起動時に `ApiServer._setup_runtime_config()` が、インストール済みパッケージ内の `<web_assets_dir>/assets/config/runtime-config.json` を読み込んで `backendUrl`・`telemetry`・`logo` を書き戻していた。既存ファイルの他のキーは保持されていた。
- 変更後: `_setup_runtime_config` は削除。`GET /dev-ui/assets/config/runtime-config.json` のルートを `/dev-ui/` の静的マウントより前に登録し、リクエストごとに `{"backendUrl": url_prefix or "", "telemetry": read_telemetry_consent(), "logo": {...}}` を `Cache-Control: no-store` で返す。テレメトリ同意の変更はリロードで反映される。`--logo-text` と `--logo-image-url` の片方だけ指定した場合の `ValueError` は維持。
- 影響: パッケージ内の `runtime-config.json` を手で編集していた、あるいはそのファイルを直接読んでいた場合は反映されない。ロゴは `--logo-text` / `--logo-image-url` で指定し、設定はサーバーの上記 URL から取得する。読み取り専用の site-packages でも書き込みが発生しなくなる。[推測] 手編集で追加していた独自キーは返らなくなる（サーバーは上記 3 キーのみ返す）。

## 新機能（Features）

### 実行キャンセル

#### Runner / Workflow / ノードの abort_signal 対応
- コミット: [ef5bbcf](https://github.com/google/adk-python/commit/ef5bbcfe51670bd211645a043914c162e7c1cd60)、closes [#4796](https://github.com/google/adk-python/issues/4796)
- 変更点: `Runner.run_async` に省略可能な `abort_signal: asyncio.Event` を追加。`InvocationContext` に紐付けられ、`base_llm_flow`・`AgentTool`・ワークフローの `_node_runner` / `_workflow` が監視して、シグナルが立つとループを抜け子タスクをキャンセルし、ジェネレーターは未処理の `CancelledError` を呼び出し側に投げずに終わる。
- 変更前は停止手段がなく、呼び出し側がジェネレーターを捨てる・タスクをキャンセルするしかなかった。指定しなければ従来どおり。
- 使い方（[ガイド](https://github.com/google/adk-python/blob/v2.11.0/docs/guides/runners/runner/abort.md) より）:
  ```python
  abort_signal = asyncio.Event()
  async for event in runner.run_async(
      user_id="u", session_id=session.id, new_message=msg,
      abort_signal=abort_signal,
  ):
      ...
      abort_signal.set()  # 次のイベントサイクルで停止
  ```

#### 中断時に合成の abort イベント・function response を記録
- コミット: [da65851](https://github.com/google/adk-python/commit/da65851a9e25005480db8164f8f0fff92ba31922)（Part of #4796）、`src/google/adk/events/_abort_events.py` 新設
- 変更点: 中断された呼び出しで応答のない function call すべてに合成エラー応答を書き込む（author / branch / isolation scope は呼び出し元を引き継ぐ）。保留中の call がなければルートエージェント名義の abort イベントを 1 件記録する。いずれも `error_code="INVOCATION_ABORTED"` で永続化される。
- 挙動の変化（コミット本文の Behavior changes）:
  - 再開可能アプリで中断→再開すると、以前はぶら下がったツールを再実行していた。今後は応答済み扱いになり、モデルに abort エラーを渡して進む。副作用のあるツールが利用者のキャンセル後に再実行されない。
  - 長時間実行ツール（確認・認証要求を含む）も保留のままにせず封じる。
  - 早期クローズやエラー後の封じ込みはベストエフォートで、失敗はログに残すのみ。
- 影響: セッション履歴に `INVOCATION_ABORTED` のイベントが現れるため、履歴を解析するコードは考慮が必要。

#### CLI: `/run_sse` のクライアント切断で abort_signal を立てる
- コミット: [3d73603](https://github.com/google/adk-python/commit/3d73603deb180a6518982b2b60f036c764f0cf7e)（`cli/api_server.py`）
- 変更点: `adk web` の Stop ボタンやタブを閉じるなどで SSE クライアントが切断した、またはジェネレーターが早期にクローズ（`GeneratorExit`）した場合に `abort_signal` を立てる。
- 変更前: クライアント切断後もサーバー側でエージェント実行が続き、トークンやツールの副作用が発生し得た。
- 影響: `adk web` / `adk api_server` 利用者は何もしなくても切断時に実行が止まる。

### ワークフロー（ツールノード）

#### ツールノードがツール確認で RequestInput により一時停止
- コミット: [ce132b9](https://github.com/google/adk-python/commit/ce132b92d471b8df903524593d863171b000a764)
- 変更前: ワークフローのツールノードで確認必須ツールを使うと、確認要求は `ctx.actions` に記録されるだけで誰も処理せず、`{'error': 'This tool call requires confirmation, ...'}` がノード出力として下流に流れ、ツールは実行されなかった。
- 変更後: 2 種類の確認要求（実行前の `require_confirmation` 判定と、実行中の `tool_context.request_confirmation(hint=..., payload=...)`）を、interrupt id `wf_tool_confirmation:<node_path>`、レスポンススキーマ `ToolConfirmation` の `RequestInput` に変換して一時停止する。承認でツールを 1 回実行、拒否で `{'error': 'This tool call is rejected.'}`。ツールノードは `rerun_on_resume=True` で作られ、再生時に完了済みノードの副作用を再実行しないよう `_replay_interceptor` が早送りする。
- 影響: 確認必須ツールをツールノードで使うグラフは、プレースホルダー出力ではなくユーザー入力待ちで止まるようになる（コミット本文で Behavior change と明記）。確認不要なツールは従来どおり即実行。ツールノード内の認証要求は引き続き未対応。

#### ノードツールの skip_summarization を tool response に伝搬
- コミット: [5a0421c](https://github.com/google/adk-python/commit/5a0421cbc58ae7b9e00ae4cd41f124863b0cbb70)
- 変更点: 動的に実行した子ノードの `ctx.actions.skip_summarization` を親コンテキストへ伝搬し、`AgentTool` と同様に `NodeTool` の出力も `skip_summarization=True` の function_response イベントに表示用出力として付ける。
- 影響: `@node` / `Workflow` をツールとして使う場合に、ノード内で `ctx.actions.skip_summarization = True` とすると、ノードの最終出力がそのままユーザー向けの最終応答になり、LLM の要約ターンが走らない。

#### ToolNode の呼び出し前後でプラグインの tool コールバックを実行
- コミット: [cfeece9](https://github.com/google/adk-python/commit/cfeece9efbb93a6ad3efb7baf7e9bf9061c83e69)
- 変更前: LlmAgent 経由のツールはプラグインの `before_tool_callback` / `on_tool_error_callback` / `after_tool_callback` を通るが、ワークフローにツールを直接ノードとして置くとすべてスキップされ、ログ・分析・キャッシュ・マスキング系プラグインが取りこぼしていた。
- 変更後: `_ToolNode` も同じ手順を通る。before が応答を返せばツールの代わりになる、on_tool_error が失敗を救済できる（救済がなければ従来どおり伝播）、after が結果を差し替えればノード出力になる。LlmAgent に設定したエージェント単位の tool コールバックは対象外（所有エージェントがいないため）。
- 影響: App に登録したプラグインの戻り値でツールノードの出力が変わり得る（Behavior change と明記）。

### ツール

#### ModelConsultTool（ターン／セッション予算つき）
- コミット: [84cc99a](https://github.com/google/adk-python/commit/84cc99abd53010817a85b51fdcdc5d4f48366769)、`src/google/adk/tools/model_consult/`
- 変更点: 実行役の `LlmAgent` が会話の主導権を保ったまま、より強いアドバイザーモデルに途中で相談する `model_consult` ツール。`google.adk.tools` から遅延エクスポート。
  - `max_uses`（ターンごと、`temp:` state）、`session_max_uses`（セッション全体、永続 state）。並列 tool call 時の協調あり。
  - 実行役の `static_instruction`・state 埋め込み済み指示文・自身以外のツール一覧をアドバイザーに渡す。
  - 上限到達で `status='limit_reached'`、質問なしで `invalid_request`、アドバイザー側のエラー／タイムアウトで `error` を返し、例外をエージェントループに投げない。
  - 既定で実行役のシステム指示に「判断前・行き詰まり時・完了宣言前に相談する」方針を追記する（`executor_instruction` で置き換え可）。
- 使い方（[ガイド](https://github.com/google/adk-python/blob/v2.11.0/docs/guides/tools/model_consult/model_consult_tool/index.md)）:
  ```python
  from google.adk import Agent
  from google.adk.tools import ModelConsultTool

  root_agent = Agent(
      name="support_executor",
      instruction="...",
      tools=[lookup_order, ModelConsultTool(max_uses=2, session_max_uses=5, thinking_level="high")],
  )
  ```
- 注意: 既定の方針では簡単なタスクでもほぼ毎回 1 回は相談が発生する（ガイドに記載）ので、コストを見て `max_uses` などを設定する。

#### model_consult のセッションコンテキスト引き継ぎ層
- コミット: [b2da4c6](https://github.com/google/adk-python/commit/b2da4c6030dcd4b4f156743201a49f01bd4ec61a)

#### model_consult でアドバイザーモデルをツールなしで呼び出す

#### （fix）model_consult のアドバイザープロンプトを単一の user コンテンツにまとめる
- コミット: [ecb429c](https://github.com/google/adk-python/commit/ecb429c941d213a1a44f739bb2ec46a23973f307)（リリースノートでは Bug Fixes。ModelConsultTool と一体なのでここに置く）

#### tool_thread_pool_config を live モード以外の同期ツールにも適用
- コミット: [c50ade3](https://github.com/google/adk-python/commit/c50ade39c88f391032887bcd1ba5e9299697d8c8)
- 変更前: `RunConfig.tool_thread_pool_config` は live モードでしか効かず、同期関数ツールは `run_async` でイベントループをブロックしていた。
- 変更後: 設定時、LlmAgent が呼ぶ同期関数ツールはツール用スレッドプールで実行される。async ツールと、ワークフローのノードとして直接使うツールは従来どおりイベントループ上。未設定なら変化なし。
- 影響: 同期ツールが重い場合、`RunConfig(tool_thread_pool_config=...)` で並行性を改善できる。[推測] スレッドで実行されるため、スレッドセーフでない同期ツールには注意。

#### data_agent ツールセットの list_accessible_data_agents にページネーション
- コミット: [46d5a2d](https://github.com/google/adk-python/commit/46d5a2d37d13303bd8ede3ee4558b850a4b3409f)
- 変更点: 既定で全ページを自動取得（上限 1000 件・100 ページ・90 秒、一時的エラーは再試行）。`page_size` / `page_token` を渡せば手動ページング、空の `page_token` は明示的に先頭ページ。時間切れなら取得済み分を `nextPageToken` と `paginationWarning` 付きで成功として返し、ページトークンが循環したらトークンなしの `paginationWarning`。1 ページ目より前の失敗はエラー（空リストと誤認させない）。
