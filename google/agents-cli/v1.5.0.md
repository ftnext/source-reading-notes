# google/agents-cli v1.5.0 変更内容の解説

- 対象リリース: https://github.com/google/agents-cli/releases/tag/v1.5.0 (2026-09-01 公開)
- 対象バージョン: v1.5.0
- 比較元バージョン: v1.4.2
- 比較URL: https://github.com/google/agents-cli/compare/v1.4.2...v1.5.0

## 比較元の決定根拠

- タグ一覧 (`git tag --sort=-creatordate`) で v1.5.0 の直前のタグが v1.4.2 (2026-08-28) であること
- リポジトリ同梱の `RELEASE_NOTES.md` で `## [1.5.0]` の直下に `## [1.4.2]` が並んでいること
- GitHub のリリース履歴でも v1.4.2 → v1.5.0 の順に公開されていること

以上 3 点が一致したため比較元は v1.4.2 で一意に決まる。

## 調査上の注意（リポジトリの性質）

- このリポジトリは **1 リリース = 1 squash コミット**（`release v1.5.0 at ...`）で公開されているミラーで、比較範囲のコミットは `5597738` の 1 つのみ、マージ済み PR も存在しない。
- そのため「関連 PR・コミット」は個別に追えず、根拠は (a) リリースノート、(b) 参照されている Issue、(c) v1.4.2 と v1.5.0 のソース差分 の 3 つに基づく。差分は 256 ファイル、+17,914 / -1,050 行。
- 以下、`[差分]` はソース差分から確認した事実、`[推測]` は差分から読み取れる範囲での推測。

## 全体の要点

1. **拡張機能（Extension）システムの新設**が最大の変更。`agents-cli extension add/list/update/remove` が追加され、組み込みコマンド（`create` / `run` / `deploy` / `eval generate` など）を外部の `run:` ベクタで上書きしたり、新コマンドを追加できる。第一弾として LangChain テンプレート（`extensions/langchain/`）が同梱。
2. **デプロイ周りの運用機能強化**: `infra show`、`deploy --update-only`、`deploy --labels`、Agent Platform API 呼び出しのリトライ。
3. **eval のスループット制御**: `eval grade/run --qps`。
4. **エラーハンドリングの改善**が多数（Issue #68, #70, #74, #77, #80, #81）。いくつかは「以前は黙って成功扱い / traceback」だったものが明示的なエラーになるため、スクリプトから呼んでいる場合は終了コードの変化に注意。
5. **スカフォールドの構造再編**: `base_templates/{go,java,typescript}` が `agents/adk_{go,java,ts}` に移動し、フレームワーク中立な `empty_py/empty_go/empty_ts/empty_java` テンプレートが追加。ルートエージェント名がプロジェクト名由来になる。

破壊的変更に近いもの（挙動が変わる）: ルートエージェント名の変更、Cloud Run のラベル `created-by=adk` → `created-by=agents-cli`、`parse_key_value_pairs` の不正入力がエラー化、マルチリージョン指定の拒否。

## 各変更項目の解説

### 1. 拡張機能システムと LangChain テンプレート【新機能】

**何が変わったか**

- 新パッケージ `src/google/agents/cli/extension/`（`_loader.py`, `_manifest.py`, `_overrides.py`, `_resolver.py`, `_refs.py`, `_spec.py`, `_sync.py`, `_trust.py`, `_paths.py`, `_schema.py`, `_compat.py`）と CLI サブコマンド `extension add/list/update/remove` が追加された。 `[差分]`
  - https://github.com/google/agents-cli/tree/v1.5.0/src/google/agents/cli/extension （CLI サブコマンドは同ディレクトリの `cmd_extension_{add,list,update,remove}.py`）
- マニフェスト `agents-cli-extension.yaml` の JSON Schema `schemas/agents-cli-extension-v1alpha1.schema.json` が追加。`commands.override` と `commands.add` の 2 種類を宣言できる。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/schemas/agents-cli-extension-v1alpha1.schema.json
- ドキュメント `docs/src/guide/extensions/{index,using,authoring,first-party}.md` が追加。
  - https://github.com/google/agents-cli/blob/v1.5.0/docs/src/guide/extensions/using.md
- `_runner.py` に `run_extension_command()` が追加され、拡張の `run:` ベクタを **シェルを介さず**サブプロセスとして実行、ユーザーの argv を末尾に付与する。実行時は環境変数 `AGENTS_CLI_DISABLE_OVERRIDES=1`（再帰防止）と `AGENTS_CLI_EXTENSION_DIR`（拡張のルート）を設定する。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/_runner.py
- `eval run` は、`eval.generate` が拡張で上書きされている場合に組み込みの ADK 実装ではなく上書きを呼ぶよう変更（`installed_override("eval.generate")` を確認）。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/eval/cmd_run.py
- 同梱の LangChain 拡張は「インストールする拡張」ではなく「スカフォールド元テンプレート」として提供され、テンプレートに含まれる `agents-cli-extension.yaml` がプロジェクトスコープで自動ロードされる。上書き対象は `playground`（`uv run langgraph dev`）、`run`、`publish.gemini-enterprise`、`eval.generate`、`eval.dataset`/`eval.optimize`（非対応メッセージ）。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/extensions/langchain/template/agents-cli-extension.yaml
  - https://github.com/google/agents-cli/blob/v1.5.0/docs/src/guide/extensions/first-party.md

**変更前 / 変更後**

- 前: CLI のコマンド群は固定。別フレームワークを使うにはフォークするか手動対応が必要。
- 後: `org/repo`（GitHub）、`--ref` 付きの任意 git ホスト、`local@../path`、first-party 短縮名からインストール可能。プロジェクトスコープ（`agents-cli-extensions.yaml` + `extensions/` に vendoring、SHA でピン留め）と `--global`（`~/.config/agents-cli/`、Windows は `%APPDATA%\agents-cli`）の 2 スコープ。同名コマンドはプロジェクトが優先。`agents-cli --help` では `[↑ <extension>]` とタグ付けされ、`agents-cli info` でも確認できる。

**利用者への影響**

- 既存ユーザーには影響なし（拡張を入れなければ従来どおり）。
- 使い方の例（ドキュメントより）:
  ```bash
  agents-cli extension add acme/acli-extensions --ref v1.0.0
  agents-cli extension list
  agents-cli create my-agent --agent google/agents-cli/extensions/langchain/template@v1.5.0 -d cloud_run
  ```
- 注意点: サードパーティ拡張は任意コードを実行するため `extension add` 時に信頼確認プロンプトが出る（`--yes` で省略）。LangChain テンプレートは Agent Runtime での `publish gemini-enterprise` や Console Playground 連携が非対応（`reasoning_engine` ルートを持たないため）とドキュメントに明記されている。

### 2. `agents-cli infra show` の追加【新機能】

- 新ファイル `src/google/agents/cli/infra/cmd_infra_show.py`。`infra single-project --apply` で作成した Terraform ルートの `terraform output` を読み、名前→値で表示する。`--json` で JSON 出力、`sensitive` 指定の出力は `<sensitive>` にマスクされ、`--include-sensitive` で平文表示。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/infra/cmd_infra_show.py
  - 補助関数は `infra/_terraform.py` に追加（`read_terraform_outputs`, `require_single_project_tf_dir`）。
- 前: Terraform ディレクトリを自分で探して `terraform output` を実行する必要があった。
- 後: `agents-cli infra show` 一発。`terraform` コマンドが必須（`require_tool("terraform")`）。
- 影響: 追加のみで既存挙動に影響なし。

### 3. `deploy --update-only`【新機能・Agent Runtime 限定】

- `cmd_deploy.py` に `--update-only` フラグを追加。`deploy/agent_runtime.py` の `deploy_to_agent_runtime(update_only=...)` で、表示名一致の既存エンジンが見つからない場合に `ClickException` で失敗させ、新規作成しない。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/deploy/cmd_deploy.py
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/deploy/agent_runtime.py
- 前: 既存エンジンが見つからなければ常に新規作成（Terraform 等で管理している設定・env var を持たない重複エンジンができる恐れ）。
- 後: `--update-only` 指定時は既存が無ければエラー。`--dry-run` の出力にもその旨が表示される。
- 制限: `deployment_target` が `agent_runtime` 以外だとエラー（コード内 TODO で Cloud Run / GKE への拡張が予告されている）。
- ソース内コメントで、表示名は一意でないため同名複数エンジンがあると最初の 1 件を黙って選ぶ既知の課題が明記されている。

### 4. `deploy --labels`【新機能・Agent Runtime / Cloud Run】

- `--labels KEY=VALUE,...` を追加。 `[差分]`
  - Agent Runtime: 既存ラベルとマージ（ユーザー指定が優先）して更新。フィールドマスクの都合で丸ごと置換されないよう `_existing_labels()` で既存を取り込む。
  - Cloud Run: `gcloud run deploy --update-labels` に変換。**既定ラベルが `created-by=adk` → `created-by=agents-cli` に変更**され、`created-by` はユーザーが上書きできない予約キー（指定すると警告して無視）。Terraform テンプレート側の `service.tf` も `created-by = "agents-cli"` に変更。
  - GKE: `--labels` はエラー（Terraform 側で管理する方針）。
- 影響: Cloud Run にデプロイしていた場合、次回デプロイでラベル `created-by` の値が変わる。ラベルでフィルタしている監視・コスト集計があれば更新が必要。

### 5. `eval --qps`【新機能】

- `eval/cmd_grade.py` に `--qps`（既定 `15.0`、正の float）を追加し、`client.evals.evaluate(config={"evaluation_service_qps": qps})` として SDK に渡す。`eval run` もこのオプションを共有・転送。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/eval/cmd_grade.py
- 前: SDK 既定のレートリミッタに固定（値は agentplatform SDK 側の既定で、本リポジトリの差分からは確認できず）。
- 後: 進捗表示に `at 15/s (--qps to change)` が出る。加えて:
  - `eval_utils.py` に `with_transient_retry()` が追加され、ローカル `custom_function` メトリクスが 408/429/5xx や `ConnectionError`/`TimeoutError` で失敗したとき `backoff` で最大 5 回・120 秒までリトライ。
  - `_warn_on_dropped_cases()` により、エラーで採点対象から外れたケース数を警告表示（従来は平均値と終了コードに隠れていた）。
- 影響: 追加のみ。レート制限を受ける場合は `--qps` を下げる。

### 6. スカフォールドのルートエージェント名をプロジェクト名由来に【挙動変更】

- `_project.py` に `root_agent_name(project_name)` を追加。`\W+` を `_` に置換し小文字化、先頭が数字なら `agent_` を付与、空なら `root_agent`。`agents/adk/app/agent.py` の `Agent(name="root_agent")` が `name="{{cookiecutter.root_agent_name}}"` に、TS の `agent.ts` も同様。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/_project.py
- Go テンプレートは例外で、ADK Go がアプリをルートエージェント名で公開する制約から `agent_directory` を名前にしている（テンプレート内 TODO に記載）。
- 前: Python は常に `root_agent`、TS は `<project>_agent`。
- 後: 例 `my-agent` → `my_agent`。この名前は OpenTelemetry の `gen_ai.agent.name` 属性としてトレースに出るため、観測基盤でエージェント名フィルタをしている場合は新規プロジェクトで値が変わる。既存プロジェクトの生成済みコードは変更されない。

### 7. Agent Platform 呼び出しのリトライ【改善】

- 新モジュール `_agent_platform.py` の `AgentPlatformClient` が `agentplatform.Client` をラップし、`retry_options={"attempts": 5, "initial_delay": 1.0}` を常に付与（SDK 既定の再試行対象 408/429/500/502/503/504、約 1s/2s/4s/8s のジッタ付き待機）。`deploy`、`eval grade` などの `agentplatform.Client` 直接生成が置き換えられ、ruff ルール（`TID251`）で直接生成を禁止。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/_agent_platform.py
- 影響: スロットリング時に失敗しにくくなる。利用者側の操作変更なし。

### 8. `agents-cli create` の前提条件エラーを明確化（Issue #68）【バグ修正】

- https://github.com/google/agents-cli/issues/68
- `scaffold/commands/create.py` に `_handle_create_errors` デコレータを追加。`ValueError` → `click.UsageError`、その他例外 → `click.ClickException`。プロジェクト名が 26 文字超・出力先が既存・ベーステンプレート不在などは、従来 `console.print` して `return`（終了コード 0）していたのを `UsageError` で終了コード非 0 に変更。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/scaffold/commands/create.py
- 影響: CI 等で `create` の終了コードを見ている場合、失敗が正しく検知されるようになる。逆に「失敗しても 0 だった」挙動に依存していたスクリプトは修正が必要。
- 併せて隠しフラグ `--quiet` が追加（`scaffold enhance/upgrade` の三方向マージ用に内部利用）。

### 9. バックグラウンドサーバー再利用時のセッションモード無視を修正（Issue #70）【バグ修正】

- https://github.com/google/agents-cli/issues/70
- `run/_local_server.py`: PID ファイルに `use_in_memory_session` を記録し、`ensure_server()` で再利用前に要求モードと比較。不一致なら既存サーバーは止めずに `ClickException`（`agents-cli run --stop-server` を案内）。フィールドの無い旧 PID ファイルは `True`（インメモリ）扱い。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/run/_local_server.py
- 前: `agents-cli run`（インメモリ）で起動したサーバーを、永続セッションを要求する eval 生成がそのまま再利用し、セッションが失われる。
- 後: 明示エラー。影響: `run` と `eval generate` を同一プロジェクトで併用している場合、一度サーバーを停止する操作が必要になることがある。

### 10. `reasoning_engine_adapter` のストリーミングが空応答になる問題を修正（Issue #80）【バグ修正・テンプレート】

- https://github.com/google/agents-cli/issues/80
- スカフォールドされる `app/app_utils/reasoning_engine_adapter.py`（`agent_runtime` ターゲット用）で、`stream_query` が同期ジェネレータであるのに `async for` していたため `TypeError` → HTTP 200 で空ボディになっていた。修正後は `__aiter__` の有無で分岐し、同期ジェネレータは `starlette.concurrency.iterate_in_threadpool` で反復、同期メソッドは `run_in_threadpool` で実行。出力は `jsonable_encoder` を通す。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/scaffold/agents/adk/app/app_utils/reasoning_engine_adapter.py
- 影響: **新規スカフォールド分のみ**に反映。既存プロジェクトは `scaffold upgrade` か手動で同ファイルを更新する必要がある。Vertex AI Console Playground / Gemini Enterprise からの `stream_query` が動くようになる。

### 11. マルチリージョン指定の禁止（Issue #81）【挙動変更・バグ修正】

- https://github.com/google/agents-cli/issues/81
- `deploy/_utils.py` に `validate_deployment_region()` を追加。正規表現 `^[a-z]+-[a-z]+\d+$` に合わないリージョン（`eu`, `us`, `global`, ゾーン名など）を `ClickException` で拒否。`deploy` 本体、Agent Runtime デプロイ、`create` のリージョン入力（対話プロンプトは再入力ループ）で適用。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/deploy/_utils.py
- 前: Agent Runtime のみ `global` を拒否。Cloud Run に `eu` を渡すと gcloud 側で分かりにくいエラー。
- 後: 早期に明確なエラー。Gemini モデル呼び出しだけをマルチリージョンにしたい場合は `.env` や `--update-env-vars` の `GOOGLE_CLOUD_LOCATION` で別指定するよう案内される。
- 移行注意: `agents-cli-manifest.yaml` の `region` にマルチリージョンを書いている既存プロジェクトは `deploy` が失敗するようになる。

### 12. 不正なプロジェクトマニフェストで明確なエラー（Issue #74）【バグ修正】

- https://github.com/google/agents-cli/issues/74
- `_project.py` の `ProjectConfig.from_dict()` が `Mapping` 以外（スカラー・リスト）を受けると `malformed agents-cli-manifest.yaml`、`create_params` が Mapping 以外なら `malformed create_params in ...` を `ClickException` で返す。空ファイル / `null` は空設定として扱う（従来どおり）。`pyproject.toml` 経由のレガシー設定も同様に型チェック。 `[差分]`
- 影響: 正常なマニフェストには影響なし。壊れたファイルで traceback ではなく 1 行エラーになる。

### 13. 古いコマンド参照の修正（Issue #77）【ドキュメント修正】

- https://github.com/google/agents-cli/issues/77
- README の `agents-cli scaffold <name>` を `agents-cli create <name>` に修正。また `infra datastore` / `data-ingestion`（削除済みコマンド）の行を削除、`scaffold enhance` の説明から RAG を除去。同梱スキル（`skills/*/SKILL.md`）や CLI ヒント文中の参照も `scaffold create <name>` などに更新。 `[差分]`
- 影響: 利用者の挙動には影響なし。

### 14. スカフォールドされた A2A エージェントがツール呼び出し/応答も転送【テンプレート変更】

- Python テンプレートの `app/app_utils/a2a.py`（v1.4.2 では `base_templates/python/{{cookiecutter.agent_directory}}/app_utils/a2a.py`、v1.5.0 では `agents/adk/app/app_utils/a2a.py`）の差分: `A2aAgentExecutor(runner=runner)` → `A2aAgentExecutor(runner=runner, force_new_version=True)`。併せて、API Gateway が `A2A-Version` ヘッダを剥がす場合の推定ロジック `_A2AServerCallContextBuilder` が削除された。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/scaffold/agents/adk/app/app_utils/a2a.py
- `[推測]` リリースノートの「ツール呼び出しと応答をテキストだけでなくクライアントに転送」は、ADK 側の新しいエグゼキュータ実装（`force_new_version=True`）が function call / function response を A2A の part として流すことに対応すると考えられる。ADK 側の実装は本リポジトリ外のため未確認。
- 影響: 新規スカフォールド分のみ。A2A クライアントが受け取るイベントにツール関連 part が増えるため、テキストのみを想定したクライアントは扱いを確認。

### 15. `agents-cli setup` がネットワーク・git 無しで動作【改善】

- スキルを `src/google/agents/cli/skills/data/` としてパッケージ内に同梱（wheel に含まれる）。`setup/cmd_setup.py` の `_install_skills()` は (1) `npx skills add <GitHub>` → 失敗時 (2) `npx skills add <同梱ディレクトリ>` → 失敗時 (3) 同梱スキルを `~/.agents/skills`（`--workspace` 時はカレント配下）に直接コピーして警告、の順にフォールバック。`--skills-source` を明示した場合はフォールバックしない。 `[差分]`
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/setup/cmd_setup.py
  - https://github.com/google/agents-cli/blob/v1.5.0/src/google/agents/cli/skills/_bundle.py
- 影響: オフライン環境でもセットアップ可能。(3) でコピーされたスキルは `agents-cli update` の管理外になる旨が警告される。

### 16. Windows でローカルパス指定の設定を持つプロジェクトの読み込み失敗を修正【バグ修正】

- リリースノート記載のみで、Issue 参照なし。squash コミットのため該当箇所を単独で特定できなかった。

## リリースノートに明記されていないが差分で確認した変更（内部変更・利用者への直接影響は限定的）

- **テンプレート構造の再編** `[差分]`: `base_templates/{go,java,typescript}` → `agents/adk_{go,java,ts}` に移動。フレームワーク中立な `agents/empty_{py,go,ts,java}` と各テンプレートの `.template/templateconfig.yaml` が追加。`remote_template.py` はテンプレート設定を `.template/templateconfig.yaml` → `agents-cli-manifest.yaml` → `pyproject.toml` の順で探し、設定が無いテンプレートは ADK テンプレートとみなす警告を出す。
